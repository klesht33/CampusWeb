# 06 — Theming System (User-Selectable Color Palettes)

## 1. Rule (CRITICAL)

**Never hardcode hex colors in new or edited UI code.** Every color in `src/**/*.tsx` is a Tailwind token of the form `k-<hex>` (e.g. `bg-k-14110e`, `text-k-d6b892`, `border-k-d6b892/30`, `from-k-efe5d4`). The `<hex>` is the *original Arena Dorada value*, used only as a stable token name. Opacity modifiers (`/30`) work.

- A token only exists if it is listed in `tailwind.config.js` → `theme.extend.colors.k` **and** in `src/theme/baseColors.ts` (`BASE_HEXES`) **and** has a default in the `:root { --k-<hex>: r g b }` block at the end of `src/index.css`. To introduce a genuinely new color, add it to all three (reuse an existing token whenever possible).
- Tailwind's `slate`, `indigo`, `violet`, `emerald`, `amber`, `cyan` palettes in `tailwind.config.js` are also mapped to the same `--k-*` variables (they were remapped to warm tones), so legacy classes like `bg-slate-900` follow the theme too.
- SVG attributes use `fill="rgb(var(--k-<hex>))"` (same for `stroke`, `stopColor`).
- `src/index.css` colors are `rgb(var(--k-<hex>) / alpha)`. Pure black/white `rgba(0,0,0,x)` shadows are intentionally left untouched.
- **Exempt (fixed) colors**: the compiler syntax-highlighting colors `f0a45d 78c5d6 c59bf0 e07a88 98c992 e58a67 b8d49c ebd09e 7d7063` stay as literal hex in `ExamSimulatorLab.tsx` so reserved words remain distinguishable in every palette (including grayscale).

## 2. Engine (`src/theme/palettes.ts`)

- Each palette is a parameter set `ThemeParams = { hue: -180..180 (rotation in degrees), sat: 0..1.8 (multiplier), mode: 'dark' | 'light' }`.
- `transformHex(hex, params)`: base color → HSL → `h + hue`, `s * sat`, and for `mode: 'light'` lightness inverted and compressed (`0.04 + (1 - l) * 0.93`) → RGB.
- `applyTheme(theme)`: writes `--k-<hex>` as space-separated `r g b` on `document.documentElement.style` for all 169 `BASE_HEXES`; for the default palette it **removes** the inline properties (falls back to `:root` defaults). Also sets `color-scheme`, `data-theme`, `data-theme-mode`.
- `loadTheme()` / `saveTheme()` persist `StoredTheme { presetId, custom }` in `localStorage['campus_unne_theme_v1']`. `src/main.tsx` calls `applyTheme(loadTheme())` **before** the first render (no flash).
- Presets (`PALETTE_PRESETS`): `arena` (default), `medianoche`, `bosque`, `amatista`, `borgona`, `coral`, `grafito`, `papel` (light), `papel-azul` (light). `presetId: 'custom'` uses `custom` params.

## 3. UI (`src/components/ThemePaletteSection.tsx`)

- Rendered by `App.tsx` when `mainNavSection === 'apariencia'` (sidebar item **Apariencia** with the `Palette` icon, plus **Paleta de colores** in the top-right profile menu).
- Contains: preset cards with live miniature preview + swatches, a custom palette editor (hue slider, intensity slider, dark/light toggle), and **Restaurar paleta original**. Changes apply instantly and persist.
- The sidebar's per-year subject list is hidden for `inicio`, `perfil` and `apariencia`.

## 4. Adding a new preset

Append an object to `PALETTE_PRESETS` (`id`, `name`, `description`, `hue`, `sat`, `mode`). No other file needs changes.

## 5. Regeneration note

`src/theme/baseColors.ts` and the `:root` block were generated by a one-time migration script. If many new tokens are added manually, keep the three lists in sync (see rule in section 1).
